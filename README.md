# padgeo: training-free pose-agnostic anomaly detection with 3D-anchored feature matching

Given a few defect-free reference photos of an object from unknown viewpoints, decide whether a query photo
from another unknown viewpoint shows a defect, and where.

The hypothesis is that a query patch should be compared only with reference patches from the *same place on
the object's surface*. A frozen feed-forward geometry model (VGGT) gives every patch a 3D location without
any training, so the experiment compares two scorers that are identical except for that constraint:

- `global_nn` (AnomalyDINO-style baseline): each query patch is scored by its nearest neighbour among all
  reference patches;
- `anchored_nn` (ours): the nearest neighbour among reference patches that are close to it in 3D.

Nothing is trained anywhere.

- `docs/UNDERSTANDING.md`: the task, data flow, assumptions and fairness guards.
- `docs/DECISIONS.md`: every design choice and its reason.
- `docs/DATA_NOTES.md`: what the dataset actually contains.
- `docs/AUDIT.md`: the integration audit.
- `docs/RESULTS.md`: tables, generated by script only.

## 1. Setup on a fresh machine (24 GB GPU)

Run every command from the repository root.

```bash
# Code, plus the SplatPose submodule that provides the reference AUPRO implementation (non-recursive:
# SplatPose's own submodules are not needed).
git clone <repository-url> stereo-ad
cd stereo-ad
git submodule update --init third_party/SplatPose

# Python 3.11 environment with the pinned dependencies (torch 2.3.1 with CUDA 12.1, VGGT at a pinned commit).
conda create -y -n padgeo python=3.11
conda activate padgeo
pip install -r requirements.txt
pip install --no-deps -e .

# MAD-Sim (970 MB) into data/MAD-Sim. The zip contains a top-level MAD-Sim/ folder.
mkdir -p data
gdown 1XlW5v_PCXMH49RSKICkskKjd2A5YDMQq -O data/MAD-Sim.zip
unzip -q data/MAD-Sim.zip -d data
python scripts/inspect_data.py --config configs/killtest_global.yaml --classes 03Mallard 04Turtle 18Obesobeso

# Formatting, lint, type checks and the full test suite (a few minutes on CPU; downloads DINOv2 ViT-S, 90 MB).
make check
```

On first use, model weights are downloaded automatically:

- VGGT-1B: about 5 GB, from Hugging Face, pinned revision.
- DINOv2 ViT-L: about 1.2 GB, from `dl.fbaipublicfiles.com`, through `torch.hub` at a pinned commit.

If that host is unreachable, download `https://dl.fbaipublicfiles.com/dinov2/dinov2_vitl14/dinov2_vitl14_pretrain.pth`
into `~/.cache/torch/hub/checkpoints/` by any other means.

## 2. Kill test (24 GB machine)

```bash
bash scripts/run_killtest.sh
```

It runs, in order:

1. `scripts/profile_geometry.py --config configs/killtest_profile.yaml`: peak VRAM and seconds per query
   for N = 2, 4, 10 in fp32 and bf16, plus how far the 3D points move between the two precisions (relative
   to the anchored radius) and the fraction of neighbour relations that flip. Output:
   `outputs/killtest_profile/profile.md` and `report.json`.
2. `scripts/run.py --config configs/killtest_global.yaml`: Mallard, Turtle and Obesobeso, N = 4, seeds 0, 1
   and 2, DINOv2 ViT-L. Output: `outputs/killtest_global/seed_*/`.
3. `scripts/run.py --config configs/killtest_anchored.yaml`: the same with VGGT-1B geometry. Output:
   `outputs/killtest_anchored/seed_*/`.
4. `scripts/make_table.py`: writes `docs/RESULTS.md`, with both methods per class and as a mean
   (mean ± std over seeds), anchored_nn's coverage, the published reference numbers and provenance.
   Also writes one figure per defect type and class into `outputs/killtest_figures/` (`scripts/visualise.py`).

Each `seed_*` directory contains `results.json` (metrics, coverage, timing and peak VRAM, cache statistics,
resolved config, git commit, library versions, hardware), `per_class.csv`, `per_query.csv`,
`scores/<class>.npz`, `config.yaml` and `run.log`.

Please send back: `docs/RESULTS.md`, `outputs/killtest_profile/profile.md`, `outputs/killtest_*/seed_*/results.json`
and `outputs/killtest_figures/`.

**Re-scoring from cache.** DINOv2 features are cached per image and VGGT geometry per image set, under
`cache/`. To change only scoring settings, copy a config, give it a new `experiment.name` and run it. Scoring
settings are radius or k, `min_confidence`, unseen mode and aggregation. The run reads everything from cache
and never loads a model; `results.json` reports cache hits and misses.

**One visualisation.** For example:

```bash
python scripts/visualise.py --configs configs/killtest_global.yaml configs/killtest_anchored.yaml \
    --seed 0 --class-name 03Mallard --query test/Burrs/0.png --out outputs/figures
```

**Real-VGGT test.** One forward pass on the experiment machine: `PADGEO_RUN_VGGT=1 pytest -m vggt_weights`.

## 3. Local development (6 GB GPU)

- `make check`: lint, types and tests. VGGT is never run locally; the tests use the model-free `fake`
  geometry backend, which returns the exact geometry of a synthetic scene in VGGT's conventions.
- `bash scripts/run_killtest.sh --smoke`: the whole kill-test path on 8 queries per class, with the fake
  backend and ViT-S. Its numbers are meaningless; it writes to `outputs/smoke_*`.
- `python scripts/run.py --config configs/local/m3_global_vits_mallard.yaml`: `global_nn` on all Mallard
  queries with ViT-S.

## 4. Repository layout

```
configs/            one YAML file per experiment (strict schema: unknown keys are errors)
  killtest_*.yaml   kill test for the 24 GB machine; smoke/ and local/ hold the development variants
padgeo/
  config.py         config schema
  pipeline.py       one experiment end to end (shared by both methods)
  data/             MAD-Sim loader, seeded reference sampling, model-input preprocessing
  geometry/         backend interface, VGGT and fake backends, unprojection, patch pooling, cache, profiling
  features/         DINOv2 patch features (cached), foreground masks
  methods/          shared scoring steps, global_nn, anchored_nn, aggregation
  eval/             metrics, evaluation, result files, cross-seed tables
  utils/            caching, logging, seeding, provenance, timing, checks, visualisation
scripts/            run.py, run_killtest.sh, make_table.py, visualise.py, profile_geometry.py, inspect_data.py
tests/              pytest suite (unit, invariance and end-to-end tests)
third_party/        SplatPose submodule (AUPRO reference implementation)
```
